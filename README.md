# SimpleChatRoom

一个基于 React、Express、Socket.IO 和 SQLite 的简单聊天室项目。项目支持匿名进入，也支持用户名密码注册与登录；用户可以创建公共或私有聊天室，在房间内实时发送消息，并查看历史消息和未读数量。

项目目前更适合本地开发、功能演示和继续扩展，不建议直接作为生产环境部署。

## 项目结构

```text
SimpleChatRoom/
├─ backend/       后端服务、SQLite 数据库和 REST/Socket.IO 接口
├─ frontend/      React + TypeScript + Vite 前端
├─ shared/        前后端共用的 TypeScript 类型
└─ README.md      项目总说明
```

更具体的说明见：[前端 README](frontend/README.md) 和 [后端 README](backend/README.md)。

## 技术栈

- 前端：React 19、TypeScript、Vite、Socket.IO Client
- 后端：Node.js、Express 5、Socket.IO、TypeScript、tsx
- 数据库：Node.js 内置 `node:sqlite`，数据库文件为 `backend/data/chat.db`
- 密码：使用 scrypt 哈希保存，不保存明文密码

## 环境要求

- Node.js 22 或更高版本。后端直接使用 `node:sqlite`，请使用支持该模块的 Node.js 版本。
- npm

## 启动项目

在项目根目录分别打开两个终端。

终端一：

```bash
cd backend
npm install
npm run dev
```

终端二：

```bash
cd frontend
npm install
npm run dev
```

默认地址：前端 `http://localhost:5173`，后端 HTTP 和 Socket.IO 均为 `http://localhost:3000`。

前端会根据当前浏览器访问的主机名连接后端的 3000 端口。通过局域网访问时，请确保两个端口可达。

## 已实现功能

- 匿名进入，自动生成游客名称；用户注册、登录和登录态恢复。token 固定有效期为 30 天，目前不会自动续期。
- 创建公共或私有聊天室；私有聊天室使用密码保护，密码只保存哈希。
- 公共聊天室对所有登录用户可见，私有聊天室只对成员可见。
- 通过房间 ID 和密码加入私有聊天室。
- Socket.IO 实时收发消息，消息先落库再广播。
- 历史消息游标分页，默认每页 50 条，最多 100 条。
- 房间未读数统计、实时推送和多标签页同步。
- 移动端侧边栏和基本错误提示。

## 尚未实现和已知缺口

### 用户身份与管理

- `admin` 和 `banned` 状态已在数据模型中，但没有管理员创建、分配权限、封禁/解封、删除用户等接口和页面。
- 没有用户列表、搜索、资料、头像、昵称修改、修改密码、找回密码、注销账号等用户中心功能。
- 没有退出全部会话的接口；前端退出只是删除本地 token。
- 没有 refresh token、token 刷新接口或服务端注销/撤销 token 接口；token 过期后需要重新登录或重新匿名进入。
- 过期 session 记录目前不会自动清理。

### 好友系统

- 没有好友申请、同意/拒绝、删除好友、好友列表和在线状态。
- 没有一对一私聊、私聊历史、已读状态或屏蔽功能。

### 匿名转正式用户

- 后端已有 `POST /api/auth/upgrade`，升级后保留原用户 ID、房间成员关系和历史消息。
- 前端没有升级表单和入口，普通用户目前无法从页面使用该功能。
- 尚未补充升级过程中的用户名确认、密码强度提示和失败重试体验。

### 其他应该具备的功能

- 房主权限：转让房主、修改房间、关闭房间、踢出成员、重置密码。
- 消息编辑、撤回、删除、回复、表情、图片/文件、链接预览和搜索。
- 浏览器通知、@提醒、声音提示和离线消息策略。
- 生产安全：CORS 白名单、HTTPS、速率限制、登录失败限制、token 撤销和输入审计。
- 数据库迁移、备份恢复、健康检查、监控和多实例部署支持。
- 多实例 Socket.IO 需要 Redis 等共享适配器；当前按单进程设计。
- 当前没有成体系的自动化单元测试、接口测试和端到端测试。

## 数据和日志

- 首次启动会自动创建 `backend/data/chat.db`，没有房间时创建“公共大厅”。
- 后端日志写入后端进程当前工作目录下的 `latest.log`。
- 数据库和日志包含运行数据，生产环境应纳入备份和访问控制。
